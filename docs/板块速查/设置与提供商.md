# 设置与提供商 板块速查

> 写给后续接手的 AI:先读 `交接文档.md` 与 `AI协作记忆.md`,本页是「设置/模型服务」的局部速查。
> 核心变更:2026-08 从「单中转站表单」升级为「多提供商 + 分用途模型引用」(RikkaHub 设置移植)。

## 二、核心概念与数据流

- **提供商**:`{id, name, baseUrl, apiKey, enabled, models: [模型id...]}` 整体序列化为 JSON 存安全存储键 `ai_providers`(含 Key,Keystore 加密)。
- **模型引用**:格式 `providerId|modelId`(模型 id 可能含 `/`,用 `|` 分隔),存各用途键 `chat_model_ref` / `fast_model_ref` / `ocr_model_ref` / `translate_model_ref` / `title_model_ref`。
- **解析链**:聊天等调用 `LlmService` → `_endpoint(modelRef)` → `AiProviders.resolve(ref)` → `find(providerId)` → 返回 (baseUrl, apiKey, model);引用为空回退 `chat_model_ref`;找不到回退第一个启用提供商。
- **迁移**:`AiProviders.migrateLegacyIfNeeded()` 在 `main()` 启动时调用——旧键 `llm_base_url/llm_api_key/llm_model` 非空且 `ai_providers` 为空时,生成「默认中转」提供商并把聊天/快速/OCR 引用迁过去(幂等)。
- **从服务商拉模型**:`AiProviders.fetchModels` 发 `GET {baseUrl}/models`(自动剥离 `/chat/completions` 后缀),解析 `data[].id`;不支持返回空列表(UI 提示可手填)。
- **测试连接**:`AiProviders.testConnection` 发最小 `/chat/completions` 请求,2xx~4xx 有响应体即视为连通。

## 三、约定与坑

- **Key 只进安全存储**:`AiProvider.apiKey` 随 JSON 存 Keystore,不要落 prefs 明文、不要进日志/源码。
- **旧键兜底**:`LlmService.isConfigured` 先查新结构,空则回退旧键(迁移前的兼容);`KeyStore.llmBaseUrl` 等旧键仍在,别删。
- **1M 上下文勾选**:存在 `KeyStore.llmSupports1m`(`'1'`=支持),决定 ContextBudget 档位;UI 在「模型」页聊天模型项下。
- **改键必同步**:模型引用键在 `AiProviders.modelRefKeys`;新增用途(如翻译/标题)要同时加 getter 与设置页入口。
- **provider id 用时间戳**:`DateTime.now().microsecondsSinceEpoch.toString()`,注意并发/毫秒级快速添加理论碰撞(实际可忽略)。
- **PopScope 未保存提示**:provider_detail 用 `this.context` + `mounted` 检查通过 lint(闭包捕获 build 的 context 会被 use_build_context_synchronously 报)。

## 四、常用改动点

- 加新「用途模型」:ai_provider.dart 加键+getter → model_roles_page 加 item → 对应服务用 `AiProviders.xxxModelRef()` 解析。
- 改提供商配置页字段:provider_detail_page.dart「连接配置」SectionCard。
- 改设置分组入口:settings_page.dart「模型与服务」SectionCard。
- 调模型拉取:ai_provider.dart `fetchModels`(端点/解析逻辑)。
