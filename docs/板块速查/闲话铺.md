# 闲话铺 板块速查

> 写给后续接手的 AI:先读 `交接文档.md` 与 `AI协作记忆.md`,本页是「闲话铺/聊天」局部速查。
> 核心链路:文本消息 → SSE 流式(可停止,思维链单独产出);图片消息 → 默认模型 → OCR 回退;本地工具调用(写操作弹确认);长期记忆注入 + 对话后自动提炼;会话按窗口长期存 SQLite。

## 二、核心概念与数据流

**发送链路**(`chat_page._send`):
1. 校验 `LlmService.isConfigured()`(新结构 `AiProviders.isChatConfigured` + 旧键兜底),未配置拦截并记日志;
2. 用户消息先落库(`_appendMessage` → `chat_service.addMessage`,事务内同时更新会话 `updated_at`);图片先 `_persistImage` 复制到 `<文档目录>/chat_imgs/msg_<ts>.{png,jpg}` 再随消息存 `image_path`;
3. `_memorySection()` 记忆注入(本地 + 外置 Nocturne,整体 15s 超时,外置 8s 超时即跳过);
4. 放一个空 assistant 气泡 → `_streamReply`:文本走 `chatStream` 流式,图片走 `chatWithImage` 非流式(150s 超时);
5. 回复完成 → 落库 assistant 消息 → `_autoExtract()` 自动提炼记忆(快速模型,失败静默)。

**SSE 流式与思维链**:
- `HttpJson.postSse` 逐行解析 `data:` 负载 → `_streamRound` jsonDecode → `delta.content` 产出 `(text, '')`、`delta.reasoning_content`(DeepSeek-R1 类)产出 `('', reasoning)`;
- `chat_page` 用 `buf`/`thinkBuf` 两个 StringBuffer 分别拼接;`thinking` 只存内存 record,**不落库**;
- 气泡顶部 `_ThinkingBlock` 折叠块(灰色小字「思考过程」,默认收起,点击展开),不参与复制/翻译(操作只针对正文);
- 停止生成:`_stopGenerating` 取消订阅 + `completer.complete()` → 返回已生成的部分文本(有部分文本则照常落库,零文本视为失败);页面销毁/切会话用 `_cancelStream`(不保留);
- 超时:整体 150s,超时先 `cancel` 再 rethrow。

**图片 / OCR 回退**(`_chatWithImage`):
- 选图压缩 1280px / quality 80;消息内容拼 `[图片]` 占位(展示时 `_displayText` 去掉);
- 先走聊天默认模型(`chatWithImage`,base64 data URL);模型不支持(抛异常,OCR 未配置时抛 `LlmImageNotSupportedError` → 气泡提示「请配置 OCR 模型」);
- 回退:OCR 模型(`ocrModelRef`)识别图片文字 → 再把「图片中的文字」作为用户消息交给聊天模型继续对话;
- 旧数据(v14 前)无 `image_path`:content 以 `[图片]` 结尾时显示占位条。

**工具调用**:
- `ToolRegistry.definitions()` 发给模型;流式 `delta.tool_calls` 按 `index` 累积(id/name/arguments 增量拼接)→ `finish_reason=='tool_calls'` 时把 assistant tool_calls + 各 `tool` 结果追加进 messages 再发下一轮,最多 `maxRounds=5`;
- 非流式 `_completeRound` 同样循环;
- 执行入口 `chat_page._execTool`:写操作(`needsConfirm`)先弹「小掌柜想帮你执行操作」确认框,确认走 `executeConfirmed`,拒绝返回「用户拒绝了该操作…」给模型;只读工具直接执行;
- 工具轮通常不产出正文,对订阅方透明。

**记忆注入与自动提炼**:
- 注入:`_memorySection` → `MemoryService.promptSectionFor(最近一条用户消息)`(中文≥2字/英文≥3字母分词,剔除「今天/明天/昨天/什么/怎么/可以」停用词;相关条目取前 10,无相关取最近 5)→ 追加 `【外置记忆检索】`(Nocturne `breath`,未配置/失败静默跳过);
- 提炼:每次回复完成触发 `MemoryExtractor.extractFrom`(最近 40 条)→ 快速模型输出 JSON(`profile/facts/summary`,容忍 ```json 围栏)→ `MemoryService.add`(同 kind 内容去重,返回 0 不算新增)→ 新增条目 `Nocturne.hold` 同步外置;失败只记日志不打断聊天。

**会话模型**:
- `chat_sessions(id, title, created_at, updated_at)`,`updated_at DESC` 决定「最近会话优先」;
- `chat_messages(id, session_id, role, content, image_path, created_at)`,索引 `idx_chat_msg_session(session_id)`;
- 首次进入直达最近会话(无则新建),切换走 `SessionListPage` 点选返回 id;v12 起取消「零点清零」,长期保存;
- 会话标题:`ChatService.createSession` 支持 `firstMessage` 截断前 12 字符(grapheme 安全,emoji 不切半),但当前两个调用点均未传参(未接线),新会话默认「新对话」直到手动重命名。

**上下文构建**(`_buildContext`):
- 双约束:`_maxContextMessages`(掌柜设置 10~800,默认 80)+ `ContextBudget.keepCount` token 预算(1M 档 100 万 / 默认 20 万,粗估 1.2 字符/token),从尾部向前取;
- 溢出部分 `_compressSlice` 用快速模型压成摘要(缓存 `_compressedUpTo/_compressedSummary`,失败回退硬裁剪且不再重试),摘要以 `【更早的对话摘要】` 用户消息开头拼回;
- 超过预警线(80 万/16.7 万)提示一次「上下文较大,建议新开会话」(每会话一次 `_contextWarned`);
- 喂给模型的是去掉 `imagePath` 的纯文本记录。

## 三、约定与坑

- **思维链不落库**:`chat_messages` 无 thinking 列;重进会话/切会话后 `thinking=null`。别往 DB 写,也别指望从 DB 读回。
- **错误气泡不落库**:`_fillErrorBubble` 只改内存(空气泡直接填 / 有文本追加 / 否则补一条),避免错误提示混进上下文。
- **`_messages` record 字段**:`(role, content, imagePath, createdAt, thinking)` —— 增删字段要同步所有构造点(`_init` 装载、`_send`、`_streamReply` 逐字更新、`_fillErrorBubble`、`_regenerate`、切会话处)。
- **`_endpoint` 提供商解析**:`modelRef` 为空用 `AiProviders.chatModelRef()`;引用格式 `providerId|modelId`(模型 id 可能含 `/`,用 `|` 分隔);`find(providerId)` 找不到回退第一个启用提供商;未配置抛 `StateError('未配置中转站 API')`。
- **`endpointFor`**:兼容只填根地址(自动补 `/chat/completions`)与填完整端点两种写法。
- **降级链**(改动时别破坏):①400/422(`_ParamsRejectedError`,常见于代理不支持 tools/max_tokens)→ 去掉 `tools/max_tokens/temperature` 重试一次;②SSE 一个事件都没收到(`_StreamNotSupportedError`,中转站忽略 stream 返回普通 JSON)→ 整段转非流式 `_complete`;两者只在第一轮(带 tools)触发:400/422 第二次仍失败直接抛出,SSE 零事件降级为非流式成功则一次性产出。
- **流式停止/超时**:取消 `StreamSubscription` 即关闭底层连接(停止生成);页面级 150s 超时;记忆注入 15s、外置检索 8s、摘要压缩 20s、翻译 60s。
- **空回复视为失败**:流式结束无文本 → AI 气泡「掌柜没有回复,请稍后重试」,不落库。
- **错误信息展示**:`_friendlyError` 剥掉 `xxx: ` 前缀、压平换行、截断 600 字符,完整显示在 AI 气泡里(可回溯);完整原因进 `AppLog`。
- **重新生成**(`_regenerate`):锚点取最后一条用户消息(含图片路径);内存删最后一条 assistant + DB 按 `created_at DESC` 删该会话最后一条 assistant 消息,再以原上下文重发。
- **图片消息**:历史图片不会重新编码喂模型(喂的是纯文本上下文);`content` 的 `[图片]` 占位与 `image_path` 双轨,展示与喂模型两套逻辑(见 `_displayText` / `_buildContext`)。
- **人设拼接**:`_buildPersona` = 基础人设 + (有名称时)「用户称你为「name」」;persona 空回退 `ApiConfig.defaultPersona`。
- **工具隐私边界**:速记/日记等隐私数据不注册工具;写操作必须 `requireConfirm`;`add_ledger` 防 NaN 用 `isFinite` 显式判断(`NaN <= 0` 为 false)。
- **记忆去重**:`MemoryService.add` 同 kind 完全相同内容返回 0 不插入(DB 唯一索引 `idx_memories_kind_content` 兜底);unique 约束冲突视作「已存在」,其它 DB 异常必须上抛。
- **日志不含密钥**:`AppLog` 不脱敏,调用方自行避免写入 Key;`HttpJson` 侧已统一 `LogSanitize.mask`。
- **发送按钮三态**:生成中=停止;有文本或待发图=发送;否则=选图。中文输入法提交走 `AppTextField` 的 `submitLocked`/`onSubmit`(显式键盘 + 完成键 + 换行兜底),别改回裸 TextField 逻辑。

## 四、常用改动点

- 改流式/思维链/工具循环/降级:→ `llm_service.dart`(`_streamRound` / `_completeRound` / `_payload` / `endpointFor`)。
- 改气泡 UI、思维链折叠块、长按菜单、欢迎语、时间戳:→ `chat_page.dart`(`_bubble` / `_ThinkingBlock` / `_showMessageActions` / `_timeLabel`)。
- 改图片链路(选图/压缩/持久化/OCR 回退/全屏预览/存相册):→ `chat_page.dart`(`_pickImage` / `_persistImage` / `_chatWithImage` / `_viewImage` / `_saveImageToGallery`)。
- 改记忆注入或自动提炼:→ `chat_page.dart`(`_memorySection` / `_autoExtract`)+ `memory_service.dart`(`promptSectionFor`)+ `memory_extractor.dart`。
- 改上下文裁剪/摘要压缩/预警:→ `context_budget.dart` + `chat_page.dart`(`_buildContext` / `_compressSlice`)+ 掌柜设置滑杆(10~800)。
- 加新工具:→ `tool_registry.dart` `_build()` 加一个 `ChatTool` 条目;写操作加 `requireConfirm: true` 与 `executeConfirmed`;确认弹窗文案在 `chat_page._describeToolCall`。
- 改会话管理(标题规则/事务/撤销):→ `chat_service.dart`;列表 UI 在 `session_list_page.dart`。
- 改掌柜资料字段:→ `shopkeeper_store.dart` + `shopkeeper_settings_page.dart`。
- 改 SSE 客户端/超时/错误脱敏:→ `http_json.dart`(`postSse` / `_send` / `HttpJsonException`)。
- 改日志落盘/上限/格式:→ `app_log.dart`。
- 改模型档位(1M 勾选):→ `KeyStore.llmSupports1m`(设置页勾选)+ `context_budget.dart` 预算常量。
