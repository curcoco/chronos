# 数据与备份 板块速查

> 写给后续接手的 AI:先读 `交接文档.md` 与 `AI协作记忆.md`,本页是「数据/备份/更新」局部速查。
> 数据全在本地:唯一 SQLite 库 `student_workbench.db`(v14)+ SharedPreferences + 文档目录媒体文件;唯一联网点是更新检查与 APK 下载。

## 一、关键文件

| 文件 | 职责 |
|---|---|
| `lib/core/services/db_helper.dart` | SQLite 单例(`DbHelper.instance`):库 `student_workbench.db`、版本常量 `dbVersion = 18`、`runMigrations` 迁移链、升级前自动备份、`close()` 释放连接(供恢复覆盖文件) |
| `lib/core/services/base_dao.dart` | 简单表 CRUD 泛型基类:子类给出 `table/fromMap/toMap/defaultOrderBy` 即得 insert/queryAll/queryWhere/deleteById/deleteByIds/updateById |
| `lib/core/services/backup_service.dart` | 导出/恢复 zip:`exportZip`(库+设置+日志+媒体+聊天图)、`restoreFromZip`(跨版本校验)、`exportDiagnosticZip`(诊断包,不含媒体) |
| `lib/core/services/settings_service.dart` | 设置项封装:`last_backup_at`、`auto_backup` 开关、`markBackupExported`、视觉设置(主题/色板/背景图,ValueNotifier 即时生效) |
| `lib/features/settings/pages/chat_files_page.dart` | 聊天图片管理:列出 `chat_imgs/`、单张删除、一键清空(不动聊天文本) |
| `lib/core/data/content_updater.dart` | 远程内容热更:启动拉 `content.json`(由 `latest.json` 推导地址),写入 `ContentStore`,失败回退本地缓存 |
| `lib/core/data/content_store.dart` | 远程内容覆盖池(内存 static 字段):各 data 类优先取覆盖池,未覆盖回退内置 const 池 |
| `lib/core/services/update_installer.dart` | APK 下载(进度/超时/完整性校验)与安装(method channel `app/install` → FileProvider + 系统安装器) |
| `lib/core/services/app_info.dart` | 版本读取(打包内置 `pubspec.yaml`)、更新检查(`latest.json`)、`compareVersions`、离线兜底 |
| `lib/core/services/app_log.dart` | 轻量日志:内存环形缓冲(500 条)+ 定期 flush 到 `app_log.txt`(约 256KB 上限),`exportText` 供备份打包 |

## 二、核心概念与数据流

### DB 版本与迁移规则

- 单文件库 `student_workbench.db`(沿用旧名,路径 `getDatabasesPath()` 下),版本 `DbHelper.dbVersion = 18`。
- 打开前 `_backupBeforeUpgradeIfNeeded`:只读探针读旧版本,若低于目标版本,先把原库复制到同目录 `backups/pre-migrate-v<旧版>-<时间戳>.db` 作回滚安全网(尽力而为,异常不阻断打开;首次安装无库则跳过)。
- `runMigrations(db, oldVersion, newVersion)` 是静态方法、公开暴露,供测试用 ffi 造旧库后直接驱动;按 `oldVersion < N` 逐段叠加执行(跳号安全,如 v9 未使用)。全新安装走 `_onCreate` 建全量 schema,不跑迁移。
- 迁移要点(写迁移代码前先读这几段):
  - v10:去 `diary_entries.entry_date` 的 UNIQUE(一天多篇)——SQLite 不能删约束,重建表搬数据。
  - v11:按列存在性补 `notes.favorite/mood`(历史 `_onCreate` 漏建,修 "no column named mood" 静默失败)。
  - v14:`chat_messages.image_path` 按列存在性补(兼容 v12 前旧库,避免重复列报错);memories 先清理重复(kind+content 只留最早)再建唯一索引 `idx_memories_kind_content`,与 `MemoryService.add` 去重查询双保险。
  - v15:`chat_messages.reasoning_content` 按列存在性补(DeepSeek 等推理模型要求历史 assistant 回传思维链,否则 400)。
  - v16:`memories` 加 `importance`(1~10,默认5)/`pinned`/`last_activated`/`activation_count`/`resolved`/`visibility`/`domain`/`tags`——记忆浮现/衰减/可见性支撑列,按列存在性补齐。
  - v17:`chat_sessions.folder_id`(归入会话文件夹)+ 新表 `session_folders(id,name,created_at)`。
  - v18:防沉迷屏幕时间——新表 `screen_app_categories(package,category,updated_at)` + `screen_usage(day,package,category,seconds, PRIMARY KEY(day,package))`(IF NOT EXISTS 建,天然幂等)。
- 表清单:`tasks / notes / wishes / coin_records / reviews / english_favs / ledger_txns / ledger_settings / kitchen_items / workouts / health_settings / memories(含 v16 浮现列) / diary_entries / plan_items / chat_sessions(含 folder_id) / chat_messages(含 image_path+reasoning_content) / user_videos / session_folders(v17) / screen_app_categories + screen_usage(v18)`。

### 备份 zip 结构(exportZip)

zip 内条目:

- `student_workbench.db` — 全部业务数据。
- `preferences.json` — SharedPreferences 全量,导出时跳过 `api_` 前缀键(密钥不入备份)。
- `backup-info.json` — 元信息(app/exported_at/note)。
- `app_log.txt` — 日志,无内容则跳过。
- `media/` — 头像/掌柜头像/背景图(按固定文件名 `avatar`/`shopkeeper_avatar`/`background` 的 jpg/png);`media/chat_imgs/` 为聊天图片目录内全部文件。图片打包失败不阻断导出。

保存位置:`ChronosBackups/chronos-backup-<yyyyMMdd-HHmmss>.zip`,优先外部可访问目录,回退应用文档目录。

### 恢复流程与跨版本校验(restoreFromZip)

1. 解压 zip;找不到 `student_workbench.db` 抛 `FormatException`(非法 zip 同样抛)。
2. `DbHelper.close()` 释放连接 → 当前库另存 `$dbPath.pre-restore`(尽力而为,回滚用)。
3. 备份 db 写入临时 `restore-probe` 只读打开取版本号:**若 `backupVersion > DbHelper.dbVersion` 抛异常「备份来自更新的版本…请先升级 App 再恢复」**——拒绝高版本降级恢复(旧 App 打开新库会因版本过高打不开、页面连锁失败)。备份库损坏时 probe 失败不阻断,交给后面 `openDatabase` 自然失败。
4. 覆盖 db 文件 → 写回 prefs(跳过 `api_` 前缀,按类型 bool/int/double/String/StringList 写回,计数进 `RestoreResult.prefsRestored`)→ 恢复 `media/` 文件(`chat_imgs/` 归位,其余按 basename 写文档目录,失败不阻断)。
5. `DbHelper.instance.database` 触发重开(应用新版本号、必要时自动迁移);返回 `RestoreResult(dbRestored, prefsRestored)`,**调用方必须刷新页面数据**。
- 诊断包 `exportDiagnosticZip` = db + `app_log.txt` + prefs(不含媒体、不含密钥),命名 `chronos-diagnostic-<时间戳>.zip`,用于问题复现。

### 自动备份

- 开关键 `auto_backup`(`isAutoBackupEnabled`/`setAutoBackupEnabled`),默认关,设置页「数据设置」可切换。
- 触发在 `lib/main.dart` `_maybeAutoBackup()`(启动时调用):开启且距上次备份(键 `last_backup_at`,ISO 8601)不足 7 天则跳过;否则延迟 8 秒静默 `exportZip()` → `markBackupExported(now)` → 记日志;失败记 `AppLog.e`,不影响启动。

### 聊天图片存储位置

- 应用文档目录 `chat_imgs/`,消息落库时本地文件路径记在 `chat_messages.image_path`(v14 起)。
- `chat_files_page.dart` 管理:列出(按路径倒序)、显示张数与总大小、单张删除与清空全部都有确认弹窗(清空提示「删除后不可恢复,不影响聊天记录文本」);只删文件、不动 DB。

### 更新检查与下载安装

- 唯一联网点:更新检查 + APK 下载(其余功能零网络)。
- 更新源:`AppInfo.updateCheckUrl()` 取 KeyStore `updateCheckUrl`,为空用默认 `http://120.76.230.67:18011/latest.json`(阿里云,`/opt/chronos-update/`)。`latest.json` 形如 `{"version":"1.2.0","note":"…","apk":"https://…/chronos-1.2.0.apk"}`。
- 检查:`installedVersion()` 读打包进 APK 的 `pubspec.yaml` 的 version;`checkUpdate` 远程可达则与远程 version 用 `compareVersions`(对外暴露,可测)比较,离线/超时回退内置兜底 `AppInfo.latestVersion = '2.3.0'`(发版时需与 pubspec 同步)。
- 下载:`UpdateInstaller.downloadApk(url, onProgress)` 到缓存目录 `chronos-update.apk`,连接/请求/块(30s)多级超时,校验空文件与完整性;失败抛 `HttpException`。
- 安装:`installApk(path)` 走 `MethodChannel('app/install')` 的 `installApk`(Android 原生 FileProvider + 系统安装器,Android 8+ 首次弹「安装未知应用」授权)。

### 内容热更

- `ContentUpdater.instance.update()` 在 `splash_page.dart` 启动时后台调用,任何失败静默(不影响启动)。
- 地址推导 `contentUrlFor(url)`:`.../latest.json` → 同目录 `.../content.json`;其它形态(如 OSS 目录)末尾补 `/content.json`(兼容用户自定义更新源)。
- 拉取成功且 JSON 为 Map 时 `_apply`:按分组 `quotes / english / auto_tasks / week_plans / long_term_goals / words / readings / writings / meals / videos / wishes` 类型安全写入 `ContentStore` 静态字段,**空列表不覆盖**;成功后写缓存 `content_cache.json`(文档目录)。
- 失败/非 200/格式错误 → `_loadCache()` 读缓存应用;无缓存则保持内置内容。`ContentStore.hasOverrides` 判断是否有远程覆盖。

## 三、约定与坑

- **DB 变更三件套**:① `dbVersion` 递增 + `runMigrations` 加 `oldVersion < N` 段,全新安装同步改 `_onCreate`(两条路径 schema 必须一致);② 加迁移测试(ffi 造旧版本库,调公开的 `DbHelper.runMigrations(db, old, new)` 验证);③ 升级前自动备份机制已内置(`_backupBeforeUpgradeIfNeeded`),别绕过/破坏。
- **恢复拒绝高版本**:备份库版本 > 当前 `dbVersion` 直接抛异常提示先升级 App;反向(低版本备份恢复到高版本 App)由重开时的迁移自动处理。
- **恢复前先 `close()`**:db 文件被占用时覆盖会失败,`restoreFromZip` 在覆盖 db 前先关连接;恢复后重开连接并刷新页面。
- **密钥不入备份**:导出与恢复都跳过 `api_` 前缀键;真正敏感的 KeyStore 值(如 `ai_providers` JSON 含 Key)本来就在安全存储、不进 prefs,自然不进备份。恢复时也刻意不覆盖本机已填密钥。
- **日志脱敏靠约定**:`AppLog` 不含自动脱敏逻辑(未确认),靠调用方自觉不写敏感信息;导出/诊断包前如要外发请人工检查日志。
- **升级前备份可能累积**:`backups/` 下 `pre-migrate-v*.db` 每次升级留一份,未见清理逻辑(未确认),长期运行会占空间。
- **`BaseDao` 只覆盖通用 CRUD**:金币聚合统计、计划 scope 过滤等复杂查询留在各自服务,别硬塞进基类。
- **版本可跳号**:迁移按 `< N` 逐段判断,但新版本号建议连续,减少心智负担。
- **内容热更别忘类型安全**:`_apply` 各分组都有 whereType/缺省回退,新增分组照抄现有模式;缓存是明文 JSON,勿放敏感内容。
